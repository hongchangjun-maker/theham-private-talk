# 관리자 운영 매뉴얼

## 최초 설치

1. Supabase Auth Admin API를 사용해 최초 관리자 계정을 만듭니다.
2. 서버 권한으로 해당 사용자의 `profiles.role`을 `super_admin`, `account_status`를 `active`로 설정합니다.
3. 브라우저 코드, SQL seed, 문서에 관리자 비밀번호를 기록하지 않습니다.
4. 관리자 로그인에 MFA를 적용하고 허용 IP가 정해져 있다면 Cloudflare Access 또는 WAF 정책을 추가합니다.

## 초대와 가입

- 초대 토큰은 32바이트 이상의 암호학적 난수로 서버에서 생성합니다.
- 데이터베이스에는 SHA-256 또는 HMAC 해시만 저장합니다.
- 이메일/도메인, 만료시각, 최대 사용 횟수, 관리자 승인 필요 여부를 함께 설정합니다.
- 가입 신청은 기본적으로 `pending`이며 회원관리자가 검토 후 `active` 또는 `rejected`로 변경합니다.

## 회원 관리

- 계정 정지, 강제 로그아웃, 역할 변경은 모두 서버에서 권한을 다시 확인합니다.
- 역할 변경과 계정 상태 변경은 `audit_logs`에 이전 값, 새 값, 대상, 요청 ID를 남깁니다.
- `read_only_admin`은 어떤 데이터도 변경할 수 없도록 API에서도 차단합니다.

## 채팅방과 회의

- 방장 변경, 참여자 강제 퇴장, 방 잠금, 관리자 메시지 삭제는 사유를 기록합니다.
- 회의 참가 토큰은 로그인 사용자, 회의 참여 권한, 시간창, 계정 상태를 확인한 뒤 서버에서만 발급합니다.
- 예약 회의는 애플리케이션 DB에서 시간을 관리하고 입장 허용 시간을 서버에서 강제합니다.
- 녹화는 기본 비활성입니다. 활성화 시 참여자 전원에게 사전 고지하고 동의하지 않은 참가자를 처리하는 정책을 마련합니다.

## 브랜드·정책 설정

- 공개 브랜드 값과 비밀 설정을 분리합니다.
- `system_settings.is_secret=true`인 값은 브라우저에 반환하지 않습니다.
- 이용약관과 개인정보처리방침 변경 시 시행일과 이전 버전을 별도 보관합니다.
