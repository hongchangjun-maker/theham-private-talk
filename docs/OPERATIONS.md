# 운영·보안·장애·백업 안내

## 보안 체크리스트

- [ ] HTTPS와 HSTS 적용
- [ ] 세션 쿠키 `Secure`, `HttpOnly`, `SameSite=Lax` 또는 더 엄격한 값 적용
- [ ] CSRF 토큰 또는 same-origin 검증 적용
- [ ] CSP, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` 적용
- [ ] 관리자 API, 초대코드 검증, 로그인에 별도 rate limit 적용
- [ ] 로그인 실패 잠금과 보안 알림 적용
- [ ] 모든 관리자 작업과 권한 변경을 감사 로그에 기록
- [ ] 업로드 MIME/확장자/크기/매직바이트 검사 및 악성코드 검사
- [ ] 파일은 비공개 버킷에 저장하고 짧은 만료의 서명 URL만 발급
- [ ] 서비스 역할 키·RealtimeKit 토큰을 서버 시크릿으로만 보관
- [ ] RLS 우회 가능한 서버 API에서도 동일한 소유권·권한 검사
- [ ] 웹훅 서명 확인과 이벤트 중복 제거 적용
- [ ] 의존성 감사, SAST, 비밀 스캔을 CI에서 실행

## 테스트 체크리스트

- [ ] 가입 전·대기·승인·거절·정지 계정 흐름
- [ ] 초대 만료·사용 횟수 초과·재사용
- [ ] 다른 방 메시지와 파일에 접근할 수 없는지 확인
- [ ] 본인 외 메시지 수정·삭제 차단
- [ ] 1:1/그룹 채팅의 실시간 수신, 재연결, 중복 방지, 페이지네이션
- [ ] 50MB 경계 업로드와 차단 확장자
- [ ] 회의 입장 시간창, 대기실, 강제 퇴장, 회의 종료
- [ ] 카메라·마이크 거부와 네트워크 끊김 안내
- [ ] 데스크톱, 390px, iPhone Safari, Android Chrome, 태블릿
- [ ] 키보드만으로 메뉴·모달·채팅 전송 가능
- [ ] PWA 설치, 오프라인 화면, 새 버전 갱신
- [ ] 관리자 각 역할의 허용/차단 매트릭스

## 장애 대응

1. `/api/status`와 Supabase/RealtimeKit 상태를 확인합니다.
2. 영향 범위와 최초 발생 시각, 최근 배포·설정 변경을 기록합니다.
3. 데이터 손상 위험이 있으면 쓰기 기능을 우선 제한합니다.
4. 비밀 유출 의심 시 API 토큰과 세션 키를 즉시 회전하고 관련 세션을 무효화합니다.
5. 복구 후 메시지 중복, 파일 무결성, 회의 웹훅 누락을 대조합니다.
6. 원인, 영향, 조치, 재발 방지 항목을 감사 가능한 사후 보고서로 남깁니다.

## 백업과 복구

- Supabase PITR 또는 일일 논리 백업을 켜고 최소 월 1회 별도 환경에 복구 시험합니다.
- Storage 객체 목록과 DB 메타데이터를 함께 백업합니다.
- 비밀 값은 백업본과 분리된 비밀 관리자에 보관합니다.
- 복구 목표(RPO/RTO)를 조직 정책으로 정하고 분기별 훈련합니다.
- 삭제 보존기간과 법적 보존 요청이 충돌할 때는 책임자 승인을 받습니다.

## 권장 보존 기본값

- 일반 메시지: 365일(조직 정책에 맞게 변경)
- 감사 로그: 최소 1년
- 회의 참가 이력: 90일
- 로그인·기기 기록: 180일
- 녹화: 기본 비활성, 활성화 시 목적에 필요한 최소 기간
